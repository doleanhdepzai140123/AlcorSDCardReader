# Alcor AU6366 (`058F:6366`)

## Status

**Verified on one computer and one macOS build.** This record does not imply compatibility
with every AU6366 board revision, firmware version, USB port, or macOS release.

## Tested setup

| Item | Tested value |
| --- | --- |
| Reader controller | Alcor AU6366 |
| USB vendor/product ID | `058F:6366` (decimal `1423:25446`) |
| USB configuration | `1` |
| USB interface | `0` |
| SCSI peripheral device type | `0` (direct-access block device) |
| SCSI vendor identification | `Multiple` |
| SCSI product identification | `Card  Reader` (two spaces between `Card` and `Reader`) |
| SCSI inquiry length | `36` |
| Computer | ASUS VivoBook M513UA-EJ710W, AMD Ryzen 7 5700U |
| macOS | Ventura `13.7.8` (`22H730`) |
| USB port mapping | Internal (`UsbConnector = 255`) |
| xHCI PCI path | `PciRoot(0x0)/Pci(0x8,0x1)/Pci(0x0,0x4)` |
| xHCI IORegistry path | `IOACPIPlane:/_SB/PCI0@0/GP17@80001/XHC1@4` |
| SSDT scope | `\_SB.PCI0.GP17.XHC1` |

The xHCI paths above are for this tested ASUS setup only. They must not be copied to
another computer.

## Profile data in the kext

The four personalities in
[`AlcorSDCardReader.kext/Contents/Info.plist`](../AlcorSDCardReader.kext/Contents/Info.plist)
match the USB interface, the card-reader driver nubs, and the SCSI logical unit. The
AU6366-specific values include:

- USB VID/PID `0x058F` / `0x6366`, configuration `1`, interface `0`;
- the SCSI inquiry strings listed above;
- SCSI characteristics and timeouts recorded in the personality;
- the `Internal` connector expectation from the tested USB map.

The kext bundle omits the machine-specific ACPI path. On the test machine, that path was
provided in OpenCore `DeviceProperties`; see [the OCAT guide](../docs/INSTALLATION_OCAT.md).

## Observed result

The test setup showed the Apple card-reader service chain and a **Card Reader** entry in
System Information. The card mounted and supported normal storage use. The no-op `SRST`
method in [`SSDT-SDCR.dsl`](../SSDT-SDCR.dsl) was used only for this setup; it is not a
general reset or power implementation.

## Source and limitations

The profile is maintained in the codeless kext's `Info.plist`; this Markdown file is its
human-readable hardware record. Apple class names and matching behavior are private
implementation details. Re-check them for each macOS release before claiming support.
